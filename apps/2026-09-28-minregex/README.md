# 2026-09-28 · minregex —— 零依赖迷你正则引擎

不使用标准库 `re`，手写的回溯式正则引擎：**模式解析（递归下降）→ AST
→ 生成器 continuation 风格的回溯匹配器**，支持捕获组与惰性量词，
对外提供 `search / match / fullmatch / finditer / findall` API，
并附带 grep 风格命令行。

## 支持的语法

| 特性 | 语法 |
|---|---|
| 字面量 | `abc`，标点转义 `\. \* \( \\` 等 |
| 任意字符 | `.`（不匹配换行） |
| 字符类 | `[a-z0-9_]`、取反 `[^0-9]`、边缘连字符 `[-a]` |
| 预定义类 | `\d \w \s` 及大写反义 `\D \W \S` |
| 分组 | 捕获组 `(...)`、非捕获组 `(?:...)` |
| 交替 | `cat\|dog`（在分组/整条内优先级最低） |
| 量词 | `* + ?` 与 `{n}` `{n,}` `{n,m}` |
| 惰性量词 | `*?` `+?` `??` `{n,m}?` |
| 锚点 | `^`（开头）、`$`（结尾） |

不支持：反向引用、命名组、lookahead/lookbehind、多行/忽略大小写标志。

## 运行方式

需要 Python 3.8+，仅使用标准库。

```bash
# grep 风格：输出匹配的行（- 表示标准输入）
python minregex.py grep '\w+@\w+\.\w+' sample.txt
echo "foo bar" | python minregex.py grep foo -

# 列出所有匹配的位置与内容
python minregex.py find '\d{4}-\d{2}-\d{2}' sample.txt
```

作为库使用：

```python
from minregex import Pattern

p = Pattern(r'(\d{4})-(\d{2})-(\d{2})')
m = p.search('on 2026-09-28 today')
m.group(0)   # '2026-09-28'
m.groups()   # ('2026', '09', '28')
p.findall('<a><b>')  # 配合 '<.*?>' 得 ['<a>', '<b>']
```

## 实现要点

1. **递归下降解析器**：文法为 `alt -> concat ('|' concat)*`、
   `concat -> piece*`、`piece -> atom 量词? 惰性?`、
   `atom -> 分组 | 字符类 | . | ^ | $ | 转义 | 字面量`。
   花括号量词在无法识别为数字区间时按字面量 `{` 处理（与主流引擎一致）。
2. **生成器 continuation 回溯**：核心函数
   `inst(node, text, i, state, cont)` 是生成器，`cont` 表示"匹配完本节点
   之后继续"的续延；交替分支依次 yield、量词通过递归 `step` 组织
   "再消费一次 / 满足退出"两种选择，天然实现深度优先回溯。
3. **贪婪与惰性**：贪婪量词先尝试多消费再退出，惰性量词先退出再多消费；
   对零宽原子（如 `(a*)*` 内层）检测位置不再前进并停止，避免无限递归。
4. **捕获组状态**：分组开始时记录起点、续延返回时记录终点；回溯期间
   用 `try/finally` 恢复旧捕获，因此被量化的分组只保留最后一次迭代的
   跨度，与标准库语义一致。
5. **搜索语义**：`search` 从每个起点重跑匹配器取第一个成功结果；
   `finditer` 在上一匹配结束位置继续，零宽匹配时前进一个位置，
   不会死循环。

## 测试

```bash
python -m unittest test_minregex -v
```

共 24 个用例。核心是**与标准库 `re` 交叉验证**：对 24 组覆盖全部
语法的模式/文本，逐项比对 `search` 的位置与匹配内容、`findall`
结果；另有日期/嵌套/量化分组的跨度比对、锚点与 fullmatch、惰性量词、
字符类边界、非法模式报错（未闭合分组/倒置区间/未知转义等），
以及 grep/find/stdin/缺文件/坏模式的 CLI 子进程冒烟。

本轮引擎与测试一次跑通；仅在跑测试前收紧了一处规则：未知字母转义
（如 `\q`）改为直接报错，与标准库 `re: bad escape` 的行为保持一致。
